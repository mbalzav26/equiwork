# 5.7.4 Transición de software y gestión de lanzamientos

El control de versiones de EquiWork se gestiona mediante Git con repositorio en GitHub, donde cada funcionalidad desarrollada se registra mediante commits descriptivos que documentan el cambio realizado. El flujo de trabajo consiste en desarrollar y probar los cambios en entorno local (Node.js, `npm install`, compilación de estilos y pruebas sobre SQLite), y una vez validado el correcto funcionamiento, desplegar la versión actualizada en el servidor de producción (VPS o DigitalOcean). El despliegue en producción se realiza mediante la sincronización del repositorio con la plataforma de hosting, configuración del archivo `.env`, instalación de dependencias (`npm install`) y reinicio del servicio Node (`npm start`). Antes de cada despliegue que implique cambios en la estructura de la base de datos, se realiza un respaldo completo del esquema y los datos (MySQL o archivo SQLite). Las versiones del sistema se documentan en el historial de cambios del informe de práctica, registrando la fecha, los ítems modificados y el responsable de cada cambio. No se implementa un esquema formal de versionado semántico dado el alcance del proyecto, pero el historial de Git y la versión declarada en `package.json` garantizan la trazabilidad completa de todas las modificaciones realizadas sobre el código fuente y de cada transición entre entorno local y producción.
