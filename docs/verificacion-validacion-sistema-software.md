# 5.7.2 Verificación y validación del sistema de software

La verificación y validación de EquiWork se realizó mediante cuatro tipos de pruebas aplicadas en distintas etapas del desarrollo. Las **pruebas unitarias de endpoints** se ejecutaron con Postman sobre cada ruta de la API (`/api`) antes de enlazarla con las vistas EJS o los scripts del cliente, comprobando códigos HTTP (200, 201, 400, 401, 404, 500) y el formato JSON devuelto en escenarios con datos válidos, campos vacíos, identificadores inexistentes y tokens inválidos o ausentes.

Las **pruebas funcionales manuales** se realizaron desde el navegador en cada módulo (login, dashboard, colaboradores, eventos, reportes y encuesta), validando flujos normales y alternos de los casos de uso, la visualización correcta de datos, mensajes de confirmación y error, y el comportamiento de acciones y menús según el rol (ADMINISTRADOR, SUPERVISOR, COLABORADOR). Las **pruebas de seguridad** verificaron que las rutas protegidas responden 401 sin token o con token inválido, que las contraseñas no se registran en texto plano en logs ni en respuestas, y que, al expirar la sesión o el JWT, el sistema impide el acceso y redirige al login. Las **pruebas de regresión** se aplicaron tras cada corrección o nueva funcionalidad, asegurando que los módulos ya estables siguieran operando con normalidad.
